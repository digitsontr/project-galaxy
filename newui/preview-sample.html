Git nedir, neden var?
Git, projenin zaman makinesidir. Her commit bir fotoğraf: “bu anda kod böyleydi”. Dal (branch) ise o fotoğraf albümünün bir kopyası — asıl kitabı bozmadan taslak yazarsın.
Bu projede sen: {{ gitBranchName }} dalındasın. Aşağıdaki resimde yeşil çizgi yayınlanan kitap (main), mavi çizgi günlük taslak (develop), mor kesikli çizgi tek bir iş.
Dallanma modeli — her nokta bir commit. Kesikli çizgi henüz birleşmemiş iş.
main = yayın
Kullanıcının gördüğü sürüm. Buraya doğrudan yazma — sadece test edilmiş iş birleşir.
develop = mutfak
Günlük geliştirme. Yeni iş buradan dallanır, bitince buraya döner.
feature = tek iş
“Giriş ekranı” gibi tek konu. Bittiğinde kapanır; dal yaşamaz.
Bir işi bitirmenin 6 adımı
1
Güncel hali al
Neden: eski kod üstüne yazarsan çatışma çıkar. git switch develop && git pull
2
İşine özel dal aç
Neden: arkadaşının işiyle karışmasın. git switch -c feature/giris-ekrani
3
Küçük commit’ler at
Neden: bozulursa tek adımı geri alırsın. git add -p sonra git commit -m "giriş butonu"
4
Uzağa gönder
Neden: yedek + ekip görsün. git push -u origin feature/giris-ekrani
5
PR / inceleme
Neden: ikinci göz hata yakalar. GitHub/GitLab’da feature → develop isteği aç.
6
Birleştir, dalı sil
Onay sonrası merge. Sonra git switch develop && git pull ve git branch -d feature/giris-ekrani
Sözlük · komut ne işe yarar
▸ Bakmak
git status — ne değişti?
git diff — satır satır fark
git log --oneline — kısa tarih
▸ Kaydetmek
git add . — sahneye al
git commit -m "…" — fotoğraf çek
git commit --amend — son fotoğrafı düzelt
▸ Dal
git switch -c <dal> — yeni dal
git switch <dal> — dal değiştir
git merge <dal> — birleştir
▸ Uzak
git pull — indir + birleştir
git push — gönder
git fetch — bak, birleştirme
▸ Geri al
git restore <dosya> — kaydedilmemişi at
git reset --soft HEAD~1 — son commit’i geri al, değişiklik kalsın
Korkma: commit’lenmiş her şey geri gelir.
▸ Acil / sürüm
hotfix/ — main’den acil yama
release/ — sürüm kilidi, sadece düzeltme
feature/ — yeni iş
